# Power BI Build Guide: Olist E-Commerce Dashboard

> **A finished version already exists:** `Olist_Ecommerce_Dashboard.pbip` (generated by `build_pbip.py`).
> Open it in Power BI Desktop and click **Refresh**. Use it as the answer key. To learn,
> rebuild it yourself from a blank file by following the steps below, then compare the two.
> The finished version has a few differences from these steps: it uses bar charts instead of
> maps (maps are disabled by default in new Power BI versions), builds the Date table in Power Query
> instead of DAX, and has "(Trend)" measures that hide the incomplete months instead of using a filter.

You build the `.pbix` yourself by following these steps. That's deliberate: in interviews you will be
asked how you modelled the data and why you wrote a measure a certain way, so you need to have
done it with your own hands. Plan for 6-10 hours the first time.

**Before you start:** run `python python/run_all.py` so that `data/processed/` contains the CSVs.

---

## Step 1: Import the data (Power Query)

1. Open Power BI Desktop and choose **Get data > Text/CSV**. Import these files from `data/processed/`:
   `fact_orders`, `fact_order_items`, `fact_payments`, `dim_customers`, `dim_products`,
   `dim_sellers`, `dim_states`, `cohort_retention`.
2. Click **Transform data** (not Load) so you can check the column types in Power Query:

| Table | Column(s) | Set type to |
|---|---|---|
| all tables | `purchase_date`, `first_order_date`, `last_order_date` | **Date** |
| fact_orders | `order_purchase_timestamp`, `order_estimated_delivery_date` | Date/Time |
| all tables | ids, `order_month`, `cohort_month`, `delay_bucket`, `rfm_code`, state codes | Text |
| all tables | `price`, `freight_value`, `order_gmv`, `product_revenue`, `payment_value`, `total_gmv` | Fixed decimal number |
| all tables | `is_*` flags, scores, counts, `order_month_num` | Whole number |
| fact_orders | `delivery_days`, `estimated_days` | Decimal number |

3. **Close & Apply.**

> Interview point: "I set types explicitly in Power Query instead of trusting auto-detection, because
> auto-detection reads only the first 200 rows and can guess wrong."

## Step 2: Date table (DAX)

Go to **Modeling > New table** and paste:

```DAX
Date =
VAR MinDate = DATE ( 2016, 9, 1 )
VAR MaxDate = DATE ( 2018, 10, 31 )
RETURN
    ADDCOLUMNS (
        CALENDAR ( MinDate, MaxDate ),
        "Year", YEAR ( [Date] ),
        "Quarter", "Q" & QUARTER ( [Date] ),
        "Month Num", MONTH ( [Date] ),
        "Month", FORMAT ( [Date], "MMM" ),
        "Year Month", FORMAT ( [Date], "YYYY-MM" ),
        "Weekday", FORMAT ( [Date], "ddd" ),
        "Weekday Num", WEEKDAY ( [Date], 2 ),
        "In Analysis Window", IF ( [Date] >= DATE ( 2017, 1, 1 ) && [Date] <= DATE ( 2018, 8, 31 ), 1, 0 )
    )
```

- **Table tools > Mark as date table** and choose the `Date` column.
- Select `Month` and set **Sort by column = Month Num**. Select `Weekday` and set **Sort by column = Weekday Num**.

## Step 3: Data model (star schema)

In **Model view**, create these relationships (all *one-to-many*, single-direction filtering):

| From (one side) | To (many side) |
|---|---|
| `Date[Date]` | `fact_orders[purchase_date]` |
| `Date[Date]` | `fact_order_items[purchase_date]` |
| `Date[Date]` | `fact_payments[purchase_date]` |
| `dim_customers[customer_unique_id]` | `fact_orders[customer_unique_id]` |
| `dim_customers[customer_unique_id]` | `fact_order_items[customer_unique_id]` |
| `dim_products[product_id]` | `fact_order_items[product_id]` |
| `dim_sellers[seller_id]` | `fact_order_items[seller_id]` |
| `dim_states[state_code]` | `dim_customers[customer_state]` |

`cohort_retention` is a pre-aggregated summary table, so it has no relationships.

Then tidy the model:
- Hide every key/id column and every column that measures replace (right-click > **Hide in report view**).
- Set `dim_states[state_name]` to **Data category = State or Province** so maps place it correctly.
  If a state lands in the wrong country, use `map_location` ("Sao Paulo, Brazil") instead.

> Why two fact tables? `fact_orders` is one row per order (order-level KPIs, delivery, reviews).
> `fact_order_items` is one row per item (product and seller analysis). Both share the `Date` and
> `dim_customers` dimensions. This is a standard **multi-fact star schema**: there is no
> fact-to-fact relationship, which avoids ambiguous filter paths.
> Rule that follows from it: **on product or seller visuals, use the `Item ...` measures.**

## Step 4: Measures

1. **Home > Enter data**, name the table `_Measures`, and click Load.
2. Create every measure from `powerbi/measures.dax` (**Modeling > New measure**, paste one at a time).
3. Format them:
   - money measures: currency, 0 decimals (`R$`)
   - `%` measures: percentage, 1 decimal
   - review measures: 2 decimals
4. Delete the empty default column of `_Measures`. The table then moves to the top of the field list.

Learn these 6 first. They come up in almost every Power BI interview:
`DIVIDE` (safe division), `CALCULATE` (changing filter context), `DISTINCTCOUNT`,
`SAMEPERIODLASTYEAR` / `DATEADD` (time intelligence), `RANKX` + `ALLSELECTED`, and
variables (`VAR ... RETURN`).

## Step 5: Theme and canvas

- **View > Themes > Browse for themes** and choose `powerbi/olist_theme.json`.
- Set every page to **16:9, 1280 x 720**. Use the same size on all pages.
- Use the same layout on every page: a title bar at the top, slicers in one row below it, KPI cards,
  then charts. Add a small "Key insight" text box on each page.

## Step 6: Report pages

### Page 1: Executive Overview
*Question: how is the business doing, and where is the money?*

| Visual | Fields |
|---|---|
| Title (text box) | Use the measure `Title Overview` in a card, or plain text |
| Slicers | `Date[Year Month]` (between / range), `dim_states[region]`, `fact_orders[main_payment_type]` |
| KPI cards (6) | `GMV`, `Orders`, `AOV`, `Customers`, `Avg Review Score`, `Late Delivery %` |
| Line + column chart | X `Date[Year Month]`, columns `Orders`, line `GMV`. Filter: `Date[In Analysis Window] = 1` |
| Line chart | X `Date[Year Month]`, values `GMV` and `GMV 3M Moving Avg` |
| Filled map | Location `dim_states[state_name]`, colour saturation `GMV` |
| Bar chart | `dim_products[category]` by `Item Revenue`, Top N = 10 (filter pane) |
| Card | `GMV YoY %` with conditional colour (green if > 0) |

### Page 2: Customers & Retention
*Question: do customers come back, and who are the valuable ones?*

| Visual | Fields |
|---|---|
| KPI cards | `Customers`, `New Customers`, `Repeat Customer Rate %`, `GMV per Customer` |
| Stacked column | X `Date[Year Month]`, values `New Customers`, `Returning Customers` |
| **Cohort heat-map (matrix)** | Rows `cohort_retention[cohort_month]`, Columns `cohort_retention[month_offset]`, Values `Cohort Retention %`. Filter `month_offset` 1-12. Conditional formatting: **background colour, gradient** (white to blue) |
| Treemap | Group `dim_customers[rfm_segment]`, values `GMV` |
| Table | `rfm_segment`, `Customers`, `GMV`, `GMV per Customer`, `Avg Review Score` |
| Bar chart | `dim_customers[customer_type]` by `Customers` and `GMV` |

### Page 3: Products & Sellers
*Question: which categories and sellers drive revenue, and which ones hurt the customer experience?*

| Visual | Fields |
|---|---|
| Slicer | `dim_products[category]` (dropdown, search on) |
| KPI cards | `Item Revenue`, `Items Sold`, `Active Sellers`, `Freight to Price %` |
| **Pareto (line + column)** | X `dim_products[category]` sorted by `Item Revenue` descending, columns `Item Revenue`, line `Category Cumulative %` (secondary axis 0-100%). Add a constant line at 80% |
| Scatter chart | Details `dim_products[category]`, X `Item Revenue`, Y `Item Avg Review`, size `Items Sold` |
| Table | `dim_products[category]`, `Category Rank`, `Item Revenue`, `Category Share %`, `Freight to Price %`, `Item Avg Review`. Data bars on revenue |
| Seller scorecard table | `dim_sellers[seller_id]`, `dim_sellers[seller_state]`, `Item Orders`, `Item Revenue`, `Item Avg Review`, `Item Late Delivery %`, `Seller CX Flag`. Visual filter: `Item Orders` >= 30. Conditional font colour: red when the flag is "Review" |

### Page 4: Delivery & Customer Experience
*Question: do we keep our delivery promise, and what happens to reviews when we don't?*

| Visual | Fields |
|---|---|
| KPI cards | `Avg Delivery Days`, `Avg Promised Days`, `Late Delivery %`, `Negative Review %` |
| **Column chart (the key chart)** | X `fact_orders[delay_bucket]`, Y `Avg Review Score`. Colour late buckets red (conditional formatting by rule) |
| Card (insight) | Measure `Insight Late Reviews` |
| Filled map | `dim_states[state_name]`, colour saturation `Late Delivery %` (diverging: green to red) |
| Line chart | X `Date[Year Month]`, values `Late Delivery %` and `Avg Review Score` (secondary axis) |
| Column chart | `fact_orders[review_score]` by `Orders` (review distribution) |
| Table | `dim_states[state_name]`, `Delivered Orders`, `Avg Delivery Days`, `Avg Promised Days`, `Late Delivery %`, `Avg Review Score` |

### Optional extras (each is a good interview talking point)
- **Report-page tooltip:** a small page (Canvas settings > Tooltip) showing `GMV`, `Orders` and `Late Delivery %` for a state, attached to the map visuals.
- **Drill-through:** a "Category Detail" page with drill-through on `dim_products[category]`.
- **Bookmarks + buttons:** a navigation bar across the 4 pages.
- **Field parameter:** let users switch the trend chart between `GMV`, `Orders` and `AOV`
  (Modeling > New parameter > Fields).

## Step 7: Check your numbers against SQL/Python

Your card values must match `outputs/INSIGHTS_REPORT.md` and `outputs/sql_results/04_headline_kpis.csv`
(with no slicers applied). If they don't, the usual causes are:
- a measure that doesn't filter `is_valid = 1`
- `purchase_date` imported as text instead of Date (the Date relationship then breaks silently)
- using `fact_orders` measures on a product visual (use the `Item ...` measures)

Being able to say "I reconciled the dashboard totals against my SQL results" is a strong interview line.
